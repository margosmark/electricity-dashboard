| 2026-10-06 (Wave J, ingestion) | The DMD hand-off lands at a new **client-only `/import`** route that parses with `parseGreenButtonUsagePoints`, plans the write in pure `lib/importPlan.ts`, and **refuses to touch `energy_data` when readings exist** until Merge (union, file wins overlaps) / Replace / Cancel is chosen; it writes only `energy_data` + clears the example flag, then navigates to `/` so the boot path re-seeds | The refresh runs on .110 and the app has no backend, so the only honest path is base64/file → browser; and an automated 2×-weekly refresh is exactly the flow that would silently truncate history if it just wrote over the key. `commitReadings` already owns that key, so `/import` ends on the same two writes + the same restore path instead of inventing a second one | An "import from file path" endpoint (adds a backend and a user-data store — kills the zero-backend invariant); routing the refresh through backup-JSON (it also rewrites `billing_day`/`extra_charges`, which a refresh has no business touching); writing `energy_data` unconditionally (an automated overwrite with no gate) |
| 2026-10-06 (Wave J, DMD) | The portal flow lives in **`ops/dmd/selectors.json`** (Playwright selector strings, ordered fallbacks, optional steps) driven by `dmd_refresh.py`, with a documented **exit-code contract** (0 filed / 3 auth / 4 no-new-data / 5 CAPTCHA-or-MFA / 6 structure / 7 not-XML / 8 credential hygiene) and DOM dumps on every structural failure | Post-login markup cannot be inspected without credentials, so hard-coding selectors would make the first redesign a code change; JSON makes it an edit. The mock-portal suite then exercises *every* exit code offline — it is what caught the fallback bug | Screen-scraping the login page with hard-coded waits; scraping the ESPI REST endpoints (that is Wave K's sanctioned OAuth path, not DMD); solving or bypassing a CAPTCHA; polling more often than 2× weekly |

| 2026-10-06 (Wave K, credentials) | The refresh token lives **server-side** in `.greenbutton/tokens.json` (0600, outside the container) and the browser holds only an HttpOnly `gb_session` cookie; the on-disk key set is pinned by a test | The card states the refresh token must be "never in the browser"; a single-user deploy also makes this strictly simpler than the open-green-button stateless pattern (no AES key, no HMAC pepper, no blob-rotation headers). | 2026-10-06 (Wave K, scope + sync) | Scope is the narrow `FB=1_3_4_5` matching a "Usage Information"-only registration, and a live sync **merges** rows by timestamp (incoming wins) instead of replacing | Agreement §1 lets the recipient use the data "only to perform its services"; we read interval usage, so billing/account blocks are not ours to request. | 2026-10-04 (Wave I, CLS) | The load→dashboard swap is made shift-free by giving the two branches of `Dashboard`'s early return **different React `key`s** (`"loading"` / `"ready"`), plus a shell that mirrors the nav + totals cards it turns into | Both branches returned a bare `<div>` at the same position, so React *reused that node* and patched className/top/height in one frame — the probe's whole CLS (0.1479) was that one node going `{0,0,358,844} → {16,131,358,713}`. Different keys make React remove the shell and insert the dashboard, so nothing on screen moves and there is nothing to score | A fixed-height skeleton matched to the *final* content height (the final height depends on whether data exists, so it can't be reserved up front); `scrollbar-gutter: stable` (only fixes the scrollbar half of the problem, not the node mutation); measuring the shift away by excluding the splash from Lighthouse |
| 2026-10-04 (Wave I, perf) | `energy.ts` stops calling `date-fns` `format()` in hot paths: six local helpers (`fmtDay`, `fmtHour`, `fmtMonthKey`, `fmtMonthLabel`, `fmtDayLabel`, `mondayOf`) build identical strings with arithmetic, plus a per-day cache for bucket labels/keys and one for the rate schedule | `format()` re-parses its pattern on every call; the pipeline issued ~35 000 of them per cold load. | 2026-10-04 (webapp always-on floor) | The webapp's base load is **interval-aware**: `energy.ts` gains `inferIntervalHours()` (modal gap between consecutive epoch-SECONDS `timestamp`s, ties → shortest) and `calculateVampire` / `calculateAlwaysOnFloor` divide the per-interval P05 by it *before* any `×24 h/day` extrapolation; `bottomFivePercentKwh` is renamed `bottomFivePercentKwhPerInterval` so the unit is in the name. `buildHeatmapData` divides a cell's sum by distinct **days**, not readings | `usage_kwh` is energy per reading interval, and Green Button / ESPI feeds are commonly 15- or 30-minute — `P05 × 24` priced a quarter-hour as a full hour, so on a 15-minute export the watts, kWh/day, $/yr and the heatmap tooltip all came out exactly 4× low, silently, because every bundled fixture is hourly (pre-fix `app.py` on a synthetic 15-min house: 0.179 kWh where the hour holds 0.717); hourly feeds divide by exactly 1.0, so no existing number moves | An hourly-only contract (reject non-hourly exports — punishes a valid file and keeps the unit lie in the helper); converting only the label while leaving `kwhPerDay = base * 24`; touching `floorCost` / `billShare` (they sum over rows and are already cadence-independent) |

| 2026-10-04 (Streamlit vampire) | Vampire $/mo is **interval-aware**: `vampire.py` measures the reading interval from the modal gap between consecutive `datetime` values and divides the P05 by it, so `estimate_base_load_kw()` returns a real kW on 15- and 30-minute exports too; the metric help names the interval it detected | Green Button / ESPI feeds are commonly 15- or 30-minute IntervalReadings — `kWh-per-reading × 24` priced a quarter-hour as a full hour and understated the figure exactly 4× ($2.86 vs $11.43 for the same synthetic house); hourly feeds divide by exactly 1.0, so no existing number moves | An hourly-only contract (reject/warn on non-hourly data — punishes a valid export and keeps the unit lie inside the helper); renaming to `base_load_kwh_per_interval` and dropping the kW claim (fixes the name, not the money) |
